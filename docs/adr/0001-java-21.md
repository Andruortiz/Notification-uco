# ADR-0001 — Java 21 LTS

**Estado**: Reemplazado por ADR-0011 (2026-10-16)
**Referenciado en**: `.specify/memory/constitution.md` ("Restricciones técnicas"), `pom.xml` (`java.version=21`), HU2-003

## Contexto

La línea base v1.0 (documento Word, 26/07/2026) fijaba Java 17. La implementación real del proyecto
terminó usando Java 21 sin que quedara registrada una decisión formal — hueco detectado al construir
la línea base documental v2.0.

## Decisión

Adoptar formalmente Java 21 LTS como versión del proyecto.

## Consecuencias

- `records` se usa de forma central para todos los value objects y DTOs (`TenantId`, `NotificationRouting`, `SendNotificationCommand`, etc.), no solo como sintaxis conveniente sino como parte del diseño del dominio.
- Pattern matching en `switch`/`instanceof` se usa en puntos como `equals()` del agregado `Notification`.
- `SequencedCollection` (`List.getLast()`) se usa para obtener el último intento de entrega en `GetNotificationStatusService` y `RequeuePendingNotificationsService`, en vez de `list.get(list.size() - 1)`.
- Los hilos virtuales (otra novedad de Java 21) se evaluaron como alternativa al modelo reactivo y se descartaron — ver ADR-0003.

## Alternativas consideradas

- **Java 17 LTS** : descartada — no tiene records maduros para el uso extensivo que requiere el dominio, ni `SequencedCollection`. Java 21 es LTS igual que 17, así que no hay riesgo de soporte adicional al actualizar.
