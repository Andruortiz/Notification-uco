# ADR-0011 — Java 25 LTS

**Estado**: Aceptado (2026-10-16). Reemplaza a ADR-0001.
**Referenciado en**: `.specify/memory/constitution.md` ("Restricciones técnicas"), `pom.xml` (`java.version=25`), `Dockerfile`, `.github/workflows/ci-cd.yml`, `.github/workflows/codeql.yml`, HU2-097

## Contexto

ADR-0001 fijó Java 21. La integración con el componente de seguridad exige el starter
`security-pep-integration-spring-boot-starter` (versión 0.1.3), que está compilado para Java 25 y no
carga en un runtime anterior. El servicio no puede delegar la autorización al PEP/PDP sin usarlo.

## Decisión

Adoptar Java 25 LTS como versión del proyecto: compilación, ejecución local, imagen Docker y
pipeline de CI/CD.

## Consecuencias

- `pom.xml`: `java.version` pasa a 25; `maven.compiler.release` lo hereda.
- `Dockerfile`: `eclipse-temurin:25-jdk` para la etapa de construcción y `eclipse-temurin:25-jre` para el runtime.
- `.github/workflows/ci-cd.yml` y `codeql.yml`: `setup-java` con la versión 25; la verificación de la imagen comprueba JRE 25.
- Todo desarrollador necesita un JDK 25 y debe apuntar `JAVA_HOME` y el SDK del proyecto en el IDE a esa versión.
- Mockito/ByteBuddy, JaCoCo, SpotBugs, Spotless, ArchUnit y Testcontainers deben funcionar con Java 25; se valida con la suite completa (`./mvnw verify`) antes de fusionar.
- Lo dicho en ADR-0001 sobre `records`, pattern matching, `SequencedCollection` y los hilos virtuales sigue vigente; son características disponibles desde Java 21.

## Alternativas consideradas

- **Quedarse en Java 21 (ADR-0001).** Descartada mientras el starter solo exista para Java 25. Si el equipo de seguridad publica un starter para Java 21, se puede reabrir esta decisión.
- **Usar la autenticación propia sin el starter.** Descartada: la guía de integración exige que el PEP decida antes de ejecutar la ruta.
